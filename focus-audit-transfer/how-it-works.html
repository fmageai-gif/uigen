Focus Audit transfer

Takes the audits you have already logged in ADHOC.xlsx and enters them into the Focus Audit SharePoint list for you — one click, no retyping.

The job it replaces

Every audit logged in the workbook has to be re-entered by hand into the Focus Audit list: twelve fields per entry, including three dropdowns, a people picker and two date-and-time fields. The data already exists. The typing is pure duplication.

By hand

~3 min

per entry, twelve fields, every one a chance to mistype a case number.

With the tool

~20 sec

per entry, unattended, with every field read back and checked before saving.

How a run works

It drives a real browser using your own SharePoint login — the same session you would use yourself. There is no service account, no stored password, and nothing leaves your PC.

  1. 01

    Read the workbook

    Finds your OneDrive-synced copy of ADHOC.xlsx automatically and reads the Audit Log sheet. It never writes to the file — the workbook is shared with the team.

  2. 02

    Pick out your rows

    Keeps only rows where auditorName is you, dated within the last seven days, and not already sent on a previous run.

  3. 03

    Translate the values

    The workbook and the list word things differently. Remote Solution (HW/SW Resolved Remotely via Phone/Chat) has to become Remote Solution; a stripped Subscription Cancellation has to become Subscription Cancellation (SubCan). It matches in both directions, and exact matches always win.

  4. 04

    Set aside what cannot be entered

    Some resolution codes have no counterpart in the list's required dropdowns. Those rows are listed up front and skipped, rather than failing halfway through a batch. You always see what was left out.

  5. 05

    Fill and verify each field

    Opens the New item form and fills all twelve fields, waiting for the directory lookup to resolve the agent's email into a real person. Every field is then read back. If a value did not land, it retries once, then stops and names the field.

  6. 06

    Save, confirm, remember

    Clicks Save and waits for the form to actually close — the panel stays open when SharePoint refuses. Only once the entry is confirmed is the audit ID written to submitted.json, so it is never sent twice.

Why the resolution code has two sources. On a valid audit the expected code is the right answer. On an invalid one, the code the agent actually used is what belongs in the record — so it comes from column R, with the (Invalid) marker removed. The parentheses in column S are part of the official code name and are always kept.

What it refuses to do

The failure that matters is not an error on screen — it is an entry that looks fine and is quietly wrong. Three rules exist to prevent that.

  • It will not guess. If a value matches no dropdown option, the run pauses and asks rather than picking something close.
  • It will not assume a field took. Every value is read back after being entered. A field that will not hold its value stops the row and names itself.
  • It will not mark a row done unless it saved. A failed row stays unrecorded and comes back on the next run, so nothing is silently lost.

A typical day: 18 entered 11 skipped — the skipped ones being resolution codes the list has no option for.

Running it

preview.bat

Prints exactly what would be sent and what would be skipped. No browser, nothing submitted. Safe to run any time.

dry-run.bat

Fills one entry in the browser and stops before Save, so you can check every field yourself.

run.bat

The real thing. Lists the rows, asks you to confirm, then enters them one by one.

Setup is once: install Python, run setup.bat, and sign in to SharePoint the first time the browser opens. After that the session is remembered.

Known limits

  • It only knows what it entered. Rows you add to the list by hand are invisible to it and could be entered again.
  • Long summaries are cut at 255 characters — the column will not accept more, and an over-long value blocks the save entirely.
  • Subscription Cancellation rows are skipped, since Call/Chat Selection Criteria offers no matching option. About a third of rows on a typical day.
  • It runs on your PC, as you. It is not a scheduled service and cannot run while you are logged out.
